# Порівняння рукописних моделей

HTR — розпізнавання рукописного тексту. Kraken підтримує HTR; сам вибір рушія не визначає, які мови та почерки модель зможе читати. Вибрана модель і спосіб підготовки рядків мають відповідати даним її навчання.

## Реалізований експеримент

Порівнюються дві моделі [FoNDUE Wölfflin](https://github.com/FoNDUE-HTR/FoNDUE_Wolfflin_Fotosammlung): GT3 для рукописних рядків і GT6 для змішаних документів того самого корпусу. Джерело й авторство: Jacsont, P., Gabay, S., Weddigen, T., *FoNDUE for the Heinrich Wölfflin Fotosammlung of the Kunsthistorisches Institut UZH*, version 1.0, 2023, CC BY 4.0. Ваги й дані зберігаються локально, не входять до Git.

Береться перетин офіційних тестових списків обох моделей. У закріпленій версії це лише **3 сторінки з 8 непорожніми рукописними рядками**. Параметр `--pages` є верхньою межею: він не розширює перетин навчальними сторінками. Розділення за авторами почерку не гарантоване.

Для обох моделей використовуються однакові зображення рядків, випрямлені за еталонними базовими лініями та контурами. Це перевірка читання, а не автоматичного пошуку рядків. Нормалізація тексту: Unicode NFC та однакові пробіли; діакритика, регістр і пунктуація залишаються. Для baseline-моделей не застосовується несумісна bbox-нормалізація Kraken.

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/prepare_htr_sample.py
.\.venv\Scripts\python.exe -X utf8 scripts/compare_htr.py
```

У `test-output/handwriting/comparison/` створюються JSON-звіт і автономна HTML-сторінка: зображення, еталон, прочитання кожної моделі, позначка розбіжності, CER/WER, кількість збоїв і SHA-256 моделей. Середня помилка зважена за числом символів/слів. Парна різниця CER і bootstrap за сторінками показують невизначеність, але на трьох сторінках не дають надійного висновку для популяції документів. Помилки запуску відображаються окремо, не перетворюються на нульовий CER.

## Другий рушій

Є експериментальний локальний адаптер [Microsoft TrOCR small handwritten](https://huggingface.co/microsoft/trocr-small-handwritten), навчений на IAM. Це модель для окремих рядків, а не цілих сторінок. На цьому переважно німецькомовному матеріалі він позначений як **контроль поза мовною спеціалізацією**; його показники не визначають кращий рушій для метрик.

```powershell
python -m pip --python .venv\Scripts\python.exe install -r requirements-htr.txt
.\.venv\Scripts\python.exe -X utf8 scripts/prepare_htr_sample.py --with-trocr
.\.venv\Scripts\python.exe -X utf8 scripts/compare_htr.py --with-trocr
```

Порівняння також доступне у **Майстерні документа → HTR**: виділіть рядок, виберіть дві локальні моделі Kraken або TrOCR і запустіть порівняння. Обидві отримають однаковий фрагмент; розбіжності підсвічуються поруч із зображенням. CER рахується тільки за власноруч перевіреним текстом без невизначених позначок і перетинів із пошкодженими ділянками. Прямокутні ручні вирізки не тотожні випрямленим базовим лініям дослідного корпусу вище, тому їхні оцінки не слід змішувати.

Для оцінки донавчання призначайте цілим книгам ролі train/validation/test у профілі книги й порівнюйте початкову та нову модель на тестових книгах у вкладці **Навчання**. Оригінал і його похідні копії не можна розносити між частинами набору. Програма перевіряє відоме навчальне походження власних нових моделей; склад навчальних даних сторонніх моделей може бути невідомий. Основними рушіями OCR цілих сторінок залишаються Kraken і Tesseract. Сторінки користувача не передаються стороннім сервісам; завантаження моделей виконується окремо, саме порівняння — без мережі.

## Коли порівняння достатньо змістовне

Потрібен окремий корпус реальних цільових метрик із перевіреними транскрипціями: кілька книг, писарів, мов, періодів, чисті й пошкоджені сторінки. Необхідно виключити дублікати та навчальні сторінки, зафіксувати правила прочитання скорочень і нерозбірливих місць до тестування. Окремо рахувати помилки в іменах, датах, номерах будинків і порядку записів; загальний CER не замінює цих перевірок.

Порівняння має дві частини: читання однакових перевірених рядків і обробка цілих сторінок з оцінкою пропущених/злитих рядків та порядку читання. PyLaia можна додати з відповідною моделлю й таким самим протоколом; у цій версії адаптера ще немає. Автоматичного голосування моделей або виправлення імен словником немає: збіг відповідей не доводить правильності.
