# Architecture

The WPF process owns interaction and a bounded `System.Threading.Channels` queue. Short requests use a fresh Python process and UTF-8 JSON. Heavy recognition/comparison/training requests share one serial JSON-lines worker, with request IDs, cancellation, timeouts, 90-second idle expiry and recycling after 24 replies. CPU Kraken pages use the local Python API inside that worker; external Kraken executables, GPU Kraken and Tesseract retain their CLI routes. No HTTP service or cloud account is involved.

The engine stores documents, pages, OCR status, records, correction history, line ground truth and settings in SQLite with WAL and foreign keys. Imports stream SHA-256 hashing, verify copied bytes and deduplicate by content hash. Source files are never written.

Page states are `pending → running → done/error`. Startup recovery changes interrupted `running` pages back to `pending`. A single-instance mutex avoids concurrent UI instances recovering each other's workers. Cancellation kills the process tree. Successful pages are not reprocessed by a resumed book job.

Preview rendering is lazy. PyMuPDF renders one PDF page at a time; Pillow decodes image frames. Display derivatives and OCR derivatives are separate files, with distinct preprocessing and region cache keys. Originals remain unchanged. Region coordinates are normalized against the original preview. OCR line boxes are relative to the derivative and are mapped back onto the full preview by the WPF layer.

Raw page OCR is separate from research records. Records can have multiple entries per page, and preserve original spelling. Region changes and successful repeated OCR archive earlier results in `recognition_history`. Verified line corrections block geometry-changing reruns.

Kraken uses its CLI baseline segmentation/recognition pipeline and ALTO serialization. Tesseract uses TSV. The application does not compare confidence scores from different models as though they were calibrated probabilities. A conservative keyword hint exists in the engine, but the UI does not automatically assign a genealogical type or invent names/dates.

The exporter generates minimal OOXML XLSX directly using the Python standard library. It keeps strings as strings, adds filters and frozen headings, and fails explicitly for Excel's 32767-character cell limit. JSON is the lossless long-text alternative. All writes to final export paths use a temporary file and atomic replacement.

Model fine-tuning is explicit, uses a new directory, and leaves the active model unchanged. Dataset splitting is by document, not randomly adjacent lines; manifests preserve provenance. CER/WER from corrected lines are labeled as selection-biased diagnostics.

`workbench.py` adds book profiles, normalized full-original annotations with edit history, derivative lineage and comparison provenance. Evidence regions can link to a record/field. Paired comparisons freeze identical line images and only score manually verified, undamaged references. Explicit dataset roles group originals and derivatives together; locally trained output hashes allow detection of known train/validation overlap in held-out comparisons. Unknown external training data cannot be certified independent. Photo transforms create separate previewable files before import. Similar-name matches are review candidates and never merge records automatically.

`library.py` adds an incremental SQLite FTS5 index with word-prefix search and highlighted snippets. Database triggers invalidate affected pages when OCR, records, line corrections or regions change. Pending/error counts accompany search results: importing photographed pages does not make their contents searchable. A dominant raster PDF page uses OCR/HTR instead of trusting a partial text layer. This is a conservative area heuristic, not a handwriting classifier.

Review resolutions bind to a result/region signature, so changed evidence reappears. Context crops include neighboring lines. History restoration selects persisted revisions and checks the current-state digest before applying a reversible edit. Restored OCR text drops historical geometry and cannot replace pages with line corrections. Column templates add geometry only to explicitly selected same-book pages without columns. Frozen evaluation manifests and images are checksum-verified and compared separately from the live library.

`layout.py` provides persisted, explicitly accepted structure proposals from existing OCR geometry or Kraken baseline segmentation. ROI coordinates map back to the full original. Geometric column clustering, paragraph gaps and optional horizontal ruling produce candidate column/entry/line regions; existing manual columns serve as anchors. These are heuristic proposals, not semantic event extraction or a trained reading-order model. Accepted regions carry editable reading-order positions; assembling a parent region uses saved descendant line texts in that order.

Scoped Kraken OCR runs against a copied crop of a saved entry/column and writes separate ALTO/JSON provenance. Results do not update page OCR, line corrections or manual annotation text. Explicit application adds unverified child lines; parent snapshots reject stale geometry. Structure proposals similarly check the annotation snapshot before acceptance. Originals remain immutable.

`sources.py` stores book-level archive/fonds/inventory/file metadata separately from page-level folios and scan URLs. Derived pages inherit from their source-page chain until their own cards are saved. Citation scan numbers refer to the original source page. Writes record previous/new metadata and reject stale card signatures when supplied. Export includes nested JSON cards and flat source columns in CSV/XLSX; citations also appear in TXT. The XLSX writer supports columns beyond Z and keeps citation data as text. URL opening is limited to HTTP/HTTPS.

`people.py` uses record ID plus field as the mention identity. Symmetric pair keys prevent duplicate reversed links. Decisions store immutable evidence snapshots, record signatures and reversible status changes in `person_link_history`. Candidate refresh checks current signatures; writes require both record signatures and the previous decision digest. This is a pairwise researcher decision store, not a merged person graph. JSON export adds link snapshots and current staleness flags; other exports retain their existing record schema.

`backups.py` snapshots SQLite with the online backup API, closes every snapshot connection before publication on Windows, and stores checksum-verified originals once in a content-addressed vault. A manifest binds the database checksum to document IDs, object hashes and lengths. Restore checks database integrity and foreign keys, validates all objects and copies into a temporary sibling before publishing a new library. Document paths are rebased. Unfinished snapshots are hidden; seven completed database snapshots are retained, while shared original objects remain. Backup listing/restoration dispatch before Engine initialization so a corrupt working database does not block recovery. External models, cache, report files and training outputs are outside the backup scope.

The main WPF window checks automatic backups at startup and every fifteen minutes, with a two-hour snapshot interval. Saved state only is backed up. F8 saves an edited OCR line as unverified before moving to the next unverified line; Ctrl+Enter explicitly verifies and advances. Ctrl+S saves edits and selected-line zoom uses existing ROI-mapped evidence geometry. Manual mouse line selection still requires explicit saving.

`genealogy.py` stores explicit person cards and unique record/field memberships. Each membership preserves the mention signature and evidence snapshot; rejected identity pairs prevent silent card grouping. Parent/spouse relationships have independent source-record signatures and cycle/duplicate validation, and withdrawal preserves old evidence. Cards show saved and current mentions separately; grouping is never inferred transitively. Genealogy export is separate JSON.

`extraction.py` persists proposal runs from explicit labels/numeric dates. The UI selects exact source-bound candidates. Application checks the record/page-text signature, one value per field, explicit overwrite permission and one-time consumption. Applied records are unverified and preserve the original text/type; JSON export includes selected spans and source text.

`operations.py` stores book-job configuration and page-task states in SQLite. A short immediate transaction claims each page; worker cancellation leaves a recoverable running task. Resume explicitly requeues interrupted tasks; failures remain until an explicit retry. Corrected pages are skipped and model file size/time changes block resume. Queues are sequential to favor bounded memory. Evaluation coverage uses SQL counts and does not generate reference text. Windows packaging copies an explicit application/source allowlist, excludes original/model/private folders and uses a per-user installed data directory.

Main-window closing defers the final Close through the Dispatcher after saving, so synchronous no-change saves cannot reenter WPF's Closing event. The UI smoke checks both normal close and save-before-close through the real worker bridge.

`research.py` stores per-mention/per-field normalized crop bounds; record-linked geometry is a fallback, followed by an explicitly labeled full-page view. Original files remain immutable. Card merge/split stores before/after state of persons, memberships and family links. An immediate write transaction checks state before applying; undo rejects later card changes. Merge redirects links only after duplicate/self/cycle validation; split never guesses relationship reassignment. Merged source cards remain archived in the database. Fact bounds are included in card JSON.

Chronology only uses explicitly Gregorian book profiles or date prefixes, bounded exact ISO/year/year-range values and non-stale main-person mentions. Other calendars and approximate/ambiguous dates receive no comparison. Parent ages and post-death events are review hints, not automatic correction or proof of invalid facts. Book dictionaries require an explicit researcher verification flag and retain source-page citations; fuzzy retrieval never changes recognized text.

`gedcom.py` previews and imports a bounded UTF-8 subset, preserves original bytes/report in SQLite and flags unsupported/unresolved structures. Import never confirms relationships or opens external media. Export emits GEDCOM 7 plus a report; unparsed/unknown-calendar dates remain notes. Confirmed current links are the default; an explicit option includes imported research claims with uncertainty notes. Shared children enter an existing couple's family only when both parent claims exist. A spouse link alone never implies parentage. Optional adjacent media files use content-addressed names, byte verification and relative GEDCOM references. Source records preserve available transcripts and source notes, including unassigned research documents; complete edit history is not embedded. `scripts/validate_gedcom7.py` can independently check a file against a separately obtained, reviewed [karbassi/GEDCOM](https://github.com/karbassi/GEDCOM) checkout. It is an optional local cross-check, not a runtime dependency or a historical-fact verifier.

`genealogy_layout.py` places the research focus above ancestors, keeps explicit couples adjacent and retains disconnected evidence branches in a separate section. Cycle detection bounds layout work. Person-card colors and typography may come from a read-only FigJam style snapshot; the original board geometry and photos remain separately available. Family document lists lead back to the corresponding working-library page and record. `--smoke-tree` renders the native tree, couple evidence and GEDCOM options without running recognition.

`duplicates.py` incrementally indexes whole and sampled-crop perceptual hashes. Low-contrast patches are excluded. Matches are candidates; same-template pages can collide. Only an explicit full-page directional decision plus a done source allows queue skipping. Fragment decisions cannot skip, and no text/record/original merging occurs. Arbitrary rotations and perspective invariance are not provided.

The current viewer is WPF, not OpenTK/OpenGL. The persistent worker uses a bounded content-validated LRU of two models, at most one TrOCR network. Segmentation models use the same cache. Training clears cached weights first. General memory-pressure adaptation and tiled viewing remain future work.

`books.py` stores `photo_books`, ordered `book_items` and `research_tasks` in the core SQLite database. Book positions are independent of immutable PDF/TIFF frame indices; gaps have no source page. Membership is exclusive at source-document level. Engine page listing groups members by saved book order without changing page IDs, records, corrections or original file bytes. Book saves validate all page identities, duplicate membership and split-role conflicts before transactionally replacing the ordering.

Workbench profile updates propagate across member documents; grouped documents participate in source-family train/test overlap checks. Source-card reads/writes and dictionary retrieval share book scope, while page-level locators remain independent. Semantic column templates preserve label/field/meaning and skip pages with existing columns. Task rectangles are normalized against the full original and remain independent of OCR ROI.

PDF export uses raster page appearances and Unicode invisible line text with OCR-ROI-to-whole-page mapping. Verified manual regions override substantially overlapping OCR lines. Native PDF text geometry is retained when recognition previously used that text layer. Unplaced text, incomplete pages and verification counts are reported in a companion JSON; no geometry is fabricated for text without bounds. Output is a working image PDF, not PDF/A or lossless archival preservation. Model comparisons retain per-book common-success denominators and failure counts; loading time is included in throughput figures.

## Evidence review additions

review_corpus.py stores entry_references, entry_reference_history and entry_corpus_runs. Source/geometry bindings invalidate changed drafts; source-family test isolation and known training-overlap checks protect frozen comparisons. fact_review.py stores assessments and history independently from records; source/record/annotation snapshots support stale detection and transaction guards. board_navigation.py resolves explicit memberships and confirmed current family links, never inferring proof from board color. sources.py preserves distinct archive locator fields in source cards and flat exports.

## Performance and model identity

schema_indexes.py idempotently installs six lookup indexes in existing and newly created feature tables. model_identity.py streams complete file/folder content manifests, including tokenizer/configuration/shards and separate segmentation models. Queues validate these identities before claiming work and recovering; older ML queues without identities require recreation, without discarding completed page OCR.

engine.handle_request returns a raw result and always closes its database connection. model_session.py retains imported Python modules/model caches, not SQLite transactions. Application-level errors return a matching JSONL reply; broken transports are not automatically retried because a command may already have committed data. The next request can create a fresh worker. CPU page Kraken preserves serialized ALTO/parsed geometry. ARCHIVEREADER_DISABLE_SESSION=1 selects the former one-shot client route.

PerformanceTelemetry.cs appends bounded request timing logs (2 MiB plus one previous file). Logs include command, transport, elapsed time and exception type; request payloads and recognized text are excluded. SQL and IPC benchmark scripts preserve result hashes and separate synthetic query timings from recognition throughput.


## 2026-10-15 library and research workspace

- Main page browser loads at most 200 metadata rows per window, with previous/next, whole-library filtering and locating a selected evidence page. Full-book recognition obtains the complete ordered IDs separately; the visible window never limits recognition scope.
- Person evidence/card operations fetch only the required record IDs. General candidate discovery remains broader by design.
- Desktop full-text search reads the current index immediately. A background worker drains changed pages in bounded transactions (25 pages / soft 150 ms budget). Dirty pages are excluded from stale results; search reports remaining indexing work. A single very large page can exceed the soft budget. FTS row IDs have a normal page index, avoiding a full virtual-table scan per replaced page.
- **Переносний пакет дослідження** snapshots the SQLite database, hash-verified originals, reports and training/evaluation artifacts. Model identities/configuration are retained; large weight files are optional. Inspect checksums before restoring into a new directory. The normal automatic backups remain smaller recovery snapshots, not substitutes for this full research package.
- **Помічник дослідника** compares original/processed previews, reviews book-scoped disagreements with explicit field labels, searches family evidence by combined fields, reuses book/column profiles and reports explicit gaps, duplicate candidates and unfinished work. It does not infer missing pages from arbitrary archive numbering or confirm people automatically.
- **Обмін PAGE / ALTO** previews one-page text regions, real baselines and supported reading order before adding new unverified annotations. Existing records and verified text remain unchanged. Original XML and provenance are retained. Export includes the exact raster and a provenance manifest. This is a supported interchange subset, not a lossless conversion of every layout hierarchy or a training reference.

Optional PERO/PaddleOCR/Docling experiments use separate environments and private reports. They are not bundled runtime engines, and successful execution does not establish historical handwriting accuracy. See [external integration trials](EXTERNAL_INTEGRATIONS.md).


## Historical reading: implemented review layer and next steps

The user has specified a visual-first reasoning workflow. The following target design distinguishes source-bound review tools from automatic contextual reasoning.

1. Establish page structure before recognition: text blocks, table headings/columns/records, illustrations/captions, margins and unresolved/damaged regions. A photo or PDF container is not a semantic document type. A layout model labeling manuscript text as a picture must remain a reviewable proposal, not automatically suppress recognition.
2. Infer context from cited source metadata and visible writing together: place of creation (distinct from current archive country), date range, institution/parish/rite, historical region, script and possible writer/style groups. No fixed year cutoff determines a language, and a language does not establish a writer's nationality.
3. Preserve diplomatic transcription separately from uncertain readings, dictionary forms and interpreted concepts. Historical spellings, inflections, abbreviations, proper names and unfamiliar words are not automatically errors. Cross-language equivalents can have different roots, not just different endings.
4. Allow language hypotheses at book, page, paragraph and word/span levels. A primarily Latin entry can contain Polish, Czech, Slovak, Hungarian, German or other names/terms. An isolated foreign term must not switch every word or the whole book into another language.
5. Recognition models first read independently from the same source pixels. A coordinator may then request a bounded second pass on a native-resolution column/line crop with surrounding evidence, compare genuine character/sequence alternatives where exposed, and consult the verified book dictionary. Raw model scores are uncalibrated signals, not probabilities of historical truth.
6. Keep visual evidence, model alternatives, context suggestions, human decisions and history distinct. Context can flag a mismatch; it cannot supply missing ink as observed text or force a modern familiar word. Retain unknown spans and mark reconstruction separately. Stop after a bounded number of passes and ask for human review when unresolved.
7. Learn only from explicitly verified examples, preserving document/writer separation and frozen independent test material. A set of letter examples must include connected forms, ligatures and variation; direct pixel-template equality is insufficient for handwriting. Agreement between models is not a training label.

`historical_reading.py` now supplies audited book/source/hand profiles, literal historical forms, human-declared cross-language concepts, source-bound model alternatives and separate uncertain decisions for saved lines/entries. Unknown words are not errors. Pixel letter exemplars are retained with source/crop hashes and an explicit hand label; analysis shows same-book, same-hand examples as advisory evidence and flags stale examples. Manual structure roles and conservative ruled-grid proposals require human review and never suppress OCR automatically. The WPF historical-reading window exposes these tools in four tabs. These are bounded review tools, not a trained historical grammar model or automatic handwriting identification. Full historical morphology, semantic language mixing, learned glyph similarity and automatic contextual re-recognition remain future work. Real trials show why these gaps matter: on AGAD301/334 scan5 a full-spread OCR missed the surname fragments and interleaved the facing-page entry.

Historical hints can now retain optional checked reference metadata (title, HTTP(S) URL, locator, resource type, independent work/witness/edition dates, scope and authenticity). Orthography/grammar/paleography kinds only match the explicitly stored literal form; they do not execute rewriting rules. The bundled JSON source catalogue is a bounded optional draft selector; unavailable/invalid data emits a warning instead of blocking reading. Catalogue entries never become lexical hints or verified references by selection alone. Full requirements are recorded in READING_REQUIREMENTS.uk.md.

`global_languages.py` supplies an independent read-only paginated publisher registry via historical_languages. JSON data is size/shape bounded and cached by file timestamp/size; responses clone row metadata. It has no language-assignment, OCR-model or translation side effects. A separate compact source catalogue remains bounded to200 listings; global bibliography records and full books are not copied into it automatically.

## Розпізнавання й порівняння (2026-10-19)
Розпізнавання вибраного рядка, запису або колонки у стандартному постійному процесі повторно використовує моделі Kraken. Для окремого рядка застосовується RecognitionTaskModel Kraken 7.1 з тією самою підготовкою, що й CLI; допоміжні процеси вирізання рядків вимкнено. Інший явно вибраний виконуваний файл залишається окремим CLI-запуском. Кеш результатів розрізняє ці шляхи та версію адаптера. Кнопка зупинки завершує власний процес; наступний запуск завантажує модель знову.

Перевірка сумнівного слова показує кандидат текстового зіставлення в квадратних дужках поруч із повним незалежним прочитанням. Вставка, пропуск або зміна поділу може дати кілька слів. Це не встановлює меж слова на фотографії, не виправляє оригінал і не підтверджує прочитання. Межі на скані можна задати вручну.

Після порівняння повних записів показується придатність моделей окремо для кожної книги замороженого набору. Нижчий спостережений CER обирається тільки за спільними успішними записами; нічия, відсутність порівнюваних записів або збої найкращої моделі не визначають переможця. Менше 20 спільних записів позначається як мала вибірка (це попередження, а не статистичний доказ достатності 20). Модель не активується автоматично. Звірені еталони створюються лише після перевірки людиною.


## Ручні рядки й контроль поділу (2026-10-19)
У майстерні → «Структура» ввімкнено читання запису за збереженими дочірніми ручними рядками. Потрібно призначити батьківський запис і порядок. Непідтверджені автоматичні пропозиції рядків не використовуються як ручні. Кожен рядок читається окремо без сегментації; порядок зберігається. Зміна дочірніх рядків скасовує придатність старого результату. Застосування показує конфлікти й не перезаписує наявний текст.

«Перевірка меж і стан книги» підсвічує малі ділянки, значні перекриття рядків одного батька й можливі проміжки. Це геометричні підказки, не доказ пропущеного тексту. Перевірка перекриттів обмежена 500 рядками, звіт — 1000 попередженнями. Для об’єднання виберіть кілька неперевірених рядків одного батька через Ctrl. Поділ одного рядка відбувається посередині висоти; нові межі можна далі виправити мишкою. Текст поділеного рядка лишається в історії та примітках, нові тексти порожні. Перевірені рядки, рядки з пов’язаними записами та рядки з дочірніми ділянками захищені від цих операцій. Операція атомарна, застарілий стан відхиляється.

Карта стану завантажує до 200 сторінок за раз. Для фотокниг зберігається порядок і явні пропущені аркуші. «Збережені рядки перевірено» не означає повноту сторінки.

«Порівняння поділу та зображень» дозволяє вибрати дві моделі сегментації й перемикати їхні пропозиції поверх одного скану. Пропозиції не застосовуються автоматично. Потрібна друга локальна придатна модель сегментації; модель читання не є її заміною. Джерело, стан розмітки та фрагмент перевіряються перед застосуванням.

Три варіанти читання — оригінал, збільшення ×2 (Lanczos) та autocontrast з cutoff=1. Похідні файли і результати окремі, пікселі оригіналу не змінюються. Обробка не відновлює втрачені штрихи й може погіршити результат; автоматичного вибору або підтвердження немає. Для збільшення діє межа 20 млн вхідних пікселів. Еталони повних записів надалі потребують ручного звірення; ці експерименти не створюють ground truth.


## Повна сторінка та продовження обробки (2026-10-19)
Майстерня → «Структура» → «Повна сторінка: обробка й перевірка». Виберіть порядок читання: колонки, табличні рядки або суцільний текст; модель A задається на вкладці HTR. Створення плану без прапорців охоплює всю сторінку. Прапорець розвороту явно ділить її на ліву та праву половини (50/50): перевірте, чи ця межа правильна. За наявності розмітки можна вибрати збережені записи/колонки й їхній порядок. Верхні ділянки плану включають свої дочірні рядки; вони не дублюються як окремі завдання.

«Продовжити» обробляє незавершені ділянки по одній, зберігаючи кожну завершену. «Зупинити» завершує власний робочий процес; після повторного відкриття завантажте останнє завдання й продовжте. Перерваний процес відновлюється лише якщо його власник більше не працює. Паралельне захоплення однієї ділянки блокується. «Повторити лише помилки» залишає завершені результати й повторює тільки невдалі. Порожня відповідь має окремий статус, а не вважається успішним прочитанням. Зміни джерела, розмітки, ваг моделей або версії обробки вимагають нового плану.

Межі вводу відокремлені від меж повернутих рядків. Зелений контур означає наявність модельного тексту, не правильність прочитання. Сірий фон поза повернутими межами — неоцінена частина зображення, а не доказ відсутності письма. Навіть ввід на всю сторінку не підтверджує повного текстового охоплення. Звіт показує цілу сторінку поруч з усіма прочитаннями, порожніми відповідями й помилками. Результати окремі від ручних записів; автоматичного перезапису немає.

Кнопка звірення записів відкриває наявний корпус для незалежного порівняння моделей, імен, дат і будинків. Без звірених людиною еталонів цей процес не дає достовірного рейтингу якості; результати нових тестів не стають еталонами.
